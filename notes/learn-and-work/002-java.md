# AI 技术专家（Staff）

## 约束

- 现有技能：精通 Java，多年后端服务器经验，熟练掌握 MySQL，熟悉 JS、Vue、Python
- 预期不会被 AI 替代的工作自主性

---

## 约束 → 选型标准

| 你的约束 | 可操作的筛选标准 |
|----------|------------------|
| 与 AI 越接近越好 | 日常工作直接涉及模型调用、推理链路、向量检索、Agent 编排、评估与治理；而非仅在前端展示 AI 能力 |
| 精通 Java + 后台履历 | 方向需能承接既有年限叙事；技术栈以 Java/Spring 生态为主力，Python 作辅助而非全盘换栈 |
| 自主性 / 不易被替代 | JD 与日常工作含架构设计、可靠性、成本与延迟权衡、安全与权限、可观测与评估；避开纯 Prompt 调优、纯内容生产、按模板接 API |
| 熟悉 Python / JS | 可快速补齐 Agent 原型、评估脚本、MCP 工具链；不必从零学编程 |
| MySQL 经验 | 可迁移至业务数据建模；AI 侧需叠加向量库、元数据存储、会话状态等，属增量而非废弃 |

**核心判断**：「与 AI 接近」不等于「做算法研究」。对 Java 后台而言，最接近 AI 且自主性高的落点，是**把大模型与 Agent 接进生产系统**——推理服务、RAG/Agent 平台、工具治理、评估与运维——而不是从零转 NLP/CV 研究员。

## 推荐方向：AI 平台 / Agent 生产工程

### 岗位在做什么（与「接近 AI」的对应关系）

| 工作块 | 与 AI 的距离 | 典型技术 |
|--------|-------------|----------|
| RAG 流水线 | 直接处理 embedding、召回、重排、上下文窗口 | Spring AI / LangChain4j、Pgvector / Milvus / ES |
| Agent 与工具调用 | 直接编排 LLM 推理步骤、状态、工具选择 | MCP、Function Calling、Agent Runtime |
| 推理服务化 | 对接模型 API 或私有化推理集群，管延迟与成本 | Spring Boot、网关、限流、缓存、批处理 |
| 评估与治理 | 定义「答得好不好」、幻觉与越权检测、A/B | 评估集、Tracing、Prometheus、审计日志 |
| 与企业系统集成 | 权限、租户、工单/订单等业务 API 的安全接入 | 既有 Java 微服务、OAuth、审计 |

这类工作的价值不在「会不会调 ChatGPT API」，而在**生产约束下的判断**：上下文怎么切、工具权限怎么设、失败怎么降级、成本怎么控、怎么证明系统变好了。

### 为什么符合「自主性高、不易被 AI 替代」

自主性高的信号（优先投递）：

- JD 出现「架构设计」「平台化」「Agent 运行时」「RAG 评估」「推理性能/成本优化」「与业务系统安全集成」
- 需要对延迟、Token 成本、命中率、幻觉率负责，而非只交付 Demo
- 团队把 AI 当**长期基础设施**建设，有 eval、监控、版本管理

自主性低、易被压缩的信号（避开）：

- 只写 Prompt、做内容审核执行、按 PRD 接第三方 API
- 「熟悉 ChatGPT 即可」、无可靠性/安全/评估要求
- 纯外包 Demo、无线上指标与迭代空间

**不易被替代的原因**（针对该方向）：

1. **生产集成复杂度**：权限、审计、多租户、与存量 Java 系统耦合——通用 Copilot 无法替你承担线上责任。
2. **领域与数据约束**：企业内部知识库、工单流、合规边界需工程化落地，不是公开模型开箱即用。
3. **评估与迭代**：谁定义指标、谁维护 golden set、谁对 regression 负责——属于工程 judgment，不是单次生成。
4. **成本与性能权衡**：并发、缓存、模型路由、长短上下文策略——后台经验直接适用。

### 为什么适合你的履历

- **主头衔可保持「Java 后端 / 高级后端」**，AI 平台为可验证专项；不必硬刚「5 年算法」。
- Java 生态已有明确路径：**Spring AI**（与 Spring Boot / Cloud 一体）、**LangChain4j**（Agent 与链式编排）；企业 Java 栈落地 AI 时优先招「自己人」而非纯 Python 算法岗。
- MySQL 经验用于业务库；AI 侧增量学习 **向量检索 + 元数据表设计**（PostgreSQL + pgvector 或专用向量库均可，与 [001-what_should_I_learn.md](./001-what_should_I_learn.md) 中的 PG 方向可叠加）。
- Python 用于评估脚本、快速验证 Prompt/Agent 逻辑，无需放弃 Java 主战场。
- JS/Vue 可参与 AI 产品前端联调，非必须但缩短与全栈团队的协作成本。

### 目标岗位（求职关键词）

主投（入口最宽、与履历最贴）：

- `Java 后端` + `Spring AI` / `大模型` / `RAG` / `Agent`
- `AI 应用开发工程师` + `Java`（筛掉纯 Python 算法岗）
- `智能体` / `Agent` + `后端` / `平台`

副投（更偏平台与自主性）：

- `AI 平台` / `大模型平台` + `Java` / `后端`
- `LLM 应用架构师` / `Agent 架构师`（年限要求更高，可作 6 个月后目标）

慎投 / 需甄别 JD：

- 纯 `算法工程师` / `NLP 研究员` 且要求顶会论文、PyTorch 深度训练
- 纯 `Prompt 工程师` 无工程与评估要求
- `AI 标注` / `内容生成` 执行岗

远程 / 外企（增量）：

- LLM Platform Engineer、Applied AI Engineer（Backend）
- AI Infrastructure（偏 Serving 时与备选方向重叠）

## 不推荐作为主方向的原因（简述）

| 方向 | 原因 |
|------|------|
| 纯大模型 CRUD 应用 | 岗位多但同质化严重，自主性低，易被「会调 API 的人」和工具链压缩 |
| Prompt 工程 / 内容向 | 与 Java 年限叙事弱相关，门槛偏低，替代风险高 |
| 算法研究 / 预训练 | 与 Java 后台履历错位，培养周期长，短期难建立可信度 |
| 纯前端 AI 封装 | 离 AI 推理与数据链路远，自主性通常低于后端平台岗 |
| 仅学 Python 转 LangChain 全栈 | 丢弃 Java 年限优势；国内大量企业 AI 层仍希望落在 Java 微服务体系内 |

## 学习路径（建议 90 天，可按 4h/天 伸缩）

按「先跑通生产闭环，再加深平台能力」排序；每周应有**可演示、可写进简历**的产出。

| 阶段 | 主题 | 产出 |
|------|------|------|
| 第 1–2 周 | 大模型 API + Spring AI 基础：Chat、Embedding、结构化输出 | 最小 Spring Boot 项目，对接 1 个国产/OpenAI 兼容 API |
| 第 3–4 周 | RAG 全链路：文档切分、向量库、检索、重排、引用溯源 | 内部文档问答 Demo + 命中率/延迟简单指标 |
| 第 5–6 周 | Agent + 工具：Function Calling、MCP Server/Client、调真实业务 API（只读） | Agent 可查订单/工单状态的 Demo；工具权限说明文档 |
| 第 7–8 周 | 生产化：限流、缓存、会话记忆窗口、异常降级、日志与 Tracing | 压测对比（并发 50/200）；失败场景 runbook |
| 第 9–10 周 | 评估与迭代：golden set、回归测试、幻觉/越权 case | 评估报告 1 份；改进前后指标对比 |
| 第 11–12 周 | 作品集与投递：README、架构图、简历专项、模拟面试题 | GitHub 仓库 + 5 道口述题（见下） |

### 技术栈建议（最小集）

- **框架**：Spring AI（主）+ LangChain4j（Agent 复杂编排时）
- **向量**：pgvector（与 PG 学习线重合）或 Milvus / Elasticsearch dense vector
- **协议**：MCP（工具标准化，企业 Agent 落地高频）
- **可观测**：Micrometer + Prometheus；LLM 调用链可用 OpenTelemetry 或 Langfuse 类工具
- **Python**：仅用于评估脚本与快速试验，不必重写主服务

### 面试口述题（自测）

1. RAG 召回率低时，你按什么顺序排查（切分、embedding、索引、query 改写）？
2. Agent 调业务 API 时，如何做权限、审计与防 Prompt 注入？
3. 如何控制 Token 成本（缓存、摘要、路由小模型/大模型）？
4. 线上回答质量回归时，评估集怎么建、怎么自动化跑？
5. Spring AI 与 LangChain4j 在你项目里如何分工？

## 风险与预期

| 风险 | 应对 |
|------|------|
| 「AI 应用岗」泛滥、含金量参差 | 用作品集 + 评估指标 + 生产化（限流/审计/runbook）筛选 JD，也筛选你自身叙事 |
| 框架迭代快（Spring AI API 变动） | 锁定版本；简历与仓库注明版本；强调问题域而非 API 细节 |
| 与纯算法岗竞争 | 不投研究员 JD；强调工程落地、Java 栈、可靠性 |
| 「接近 AI」预期过高 | Serving/训练更贴近模型本体，但 ramp 长；平台岗是更现实的 90 天切入点 |

**一句话**：以「Java 高级后端 + AI 平台/Agent 生产工程」为主头衔，90 天内做出带 RAG、Agent、MCP、评估与限流的完整 Demo；中长期可叠加 PG/向量检索或 LLM Serving，向更靠近模型本体的岗位演进。
