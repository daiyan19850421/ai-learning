## 三、三阶段：每次只盯一个阶段

### 阶段 0：现在 → 30 天（唯一任务：作品集 + 开始投递）

**不要做**：90 天全量 AI 计划、PG HA/Patroni、LLM Serving、算法、纯刷课。

**只做一件事**：做一个 **合并项目** ——

| 项目名（简历用） | 技术内容 |
|------------------|----------|
| **企业知识库 RAG 服务（Java + PostgreSQL/pgvector）** | Spring AI + 文档入库 + 向量检索 + 带引用问答 + 20 题评估集 + 至少 1 个优化数字 +（第 3 周起）1 个 MCP 只读工具或 SQL/索引优化 |

**为什么一个项目就够**：同时覆盖 001（PG/性能）和 002（AI 平台），面试只讲一个故事，避免「两个半吊子 Demo」。

**30 天节奏（4h/天）**：

| 周 | 做什么 | 产出 |
|----|--------|------|
| 1 | Spring AI + PG + pgvector，灌入固定语料 | 能问能答 |
| 2 | 20 题 golden set，调 chunk/topK，记录命中率/延迟 | 有数字的调优笔记 |
| 3 | MCP 只读工具 **或** 向量检索 SQL/索引优化（二选一深挖） | 差异化点 1 个 |
| 4 | README、简历一节、5 道口述题；**投递** | 开始面试 |

**第 3 周即可投**：`Java 后端` + `大模型/RAG/Spring AI` **或** `Java` + `PostgreSQL/性能`（同一项目换关键词）。

**文档指向**：

- PG 细节：[PostgreSQL-deep-engineer/003-week-plan.md](./PostgreSQL-deep-engineer/003-week-plan.md)（取执行计划、慢查询部分，**不要按 30 天 PG-only 做**）
- AI 细节：[002-java.md](./002-java.md)（取 RAG/eval/MCP，**不要按 90 天全做**）

### 阶段 1：30 天 → 6–12 个月（唯一任务：拿到/稳住资深 Java + 把专项做深）

**目标岗位**：高级/资深 Java 后端（JD 含数据库或 AI 生产，避开纯 CRUD、纯 Prompt）。

**深化顺序**（一次只加深一项，在职/换岗后亦然）：

1. RAG 评估体系 + 限流降级 + runbook  
2. PG 慢查询 / 连接池 / 压测（与 RAG 同库）  
3. Agent 工具权限与审计  

**还不做**：Staff 答辩材料、内核 C 开发、模型训练。

**文档指向**：[PostgreSQL-deep-engineer/002-career-outlook.md](./PostgreSQL-deep-engineer/002-career-outlook.md)

---

### 阶段 2：1–3 年（唯一任务：Staff = 域内 Top + 标准/平台化）

**Staff 不是新方向**，是阶段 1 的放大：你在 **「Java 服务的生产治理（含 AI 层 + 数据层）」** 成为团队默认咨询人，并产出规范/平台。

**能力清单**（详见 Staff 与 AI 分工）：

- 深度：一条域打穿  
- 责任：指标、上线、事故签字  
- 组织：跨团队推动、RFC、带人  

**文档指向**：[003-staff-ai-retain.md](./003-staff-ai-retain.md)

## 四、你的约束 → 最终怎么满足（对照表）

| 你关心的 | 怎么满足 | 阶段 |
|----------|----------|------|
| 好找工作、紧缺 | Java + RAG/PG 组合专项，比纯 CRUD 或纯调 API 稀缺 | 0 |

| 贴近 AI | RAG/Agent/MCP 在合并项目里 | 0 |
| 不被 AI 取代 | 做 **签字层**（评估门槛、权限、SQL 变更、发布），见 003 | 0–2 |
| 资深 Java / Staff | 主头衔不变，专项支撑晋升叙事 | 1–2 |
| 北京 | 主投本地 Backend；远程作增量 | 0 起 |

## 五、现在不做清单（用来砍焦虑）

以下 **明确推迟**，出现「是不是也该学」时，答案为 **否**：

| 不做（现阶段） | 何时再考虑 |
|----------------|------------|
| NLP/CV 算法、论文、训练 | 基本不做，与履历不符 |
| 纯 Prompt 工程 | 不做 |
| K8s/SRE 作主方向 | 阶段 1 之后，按岗位补 |
| LLM Serving / vLLM / C++ | 阶段 2 或换岗后 |
| PG Patroni / 全套 DBA 驻场 | 阶段 1 后，且筛 JD 避驻场 |
| 再开一个与 RAG 无关的 PG 仓库 | 不做，合并为一个项目 |
| 90 天 AI 计划全盘执行 | 压缩进阶段 0 的 30 天版 |
| 同时投算法岗、DBA 驻场、纯 AI Demo 岗 | 不做，浪费简历 |

## 九、一句话收束
