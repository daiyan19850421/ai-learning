## 三、能力画像（v2 评估）

### 3.1 总判定（一句话）

**市场可叙事定位：10 年服务器（Java）研发，政企指挥调度 + 金融客户洞察双域经验；综合评估为 **资深 Java 后端（Senior）** 区间，具备冲击 **高级专家 / 应用架构（小团队）** 的年限与场景基础；**PostgreSQL 专项、AI 生产、Staff 级跨组织影响力** 仍缺可验证材料，不宜作主投标签。**

| 维度 | 依据 | 可验证度 | 评估结论 |
|------|------|----------|----------|
| Java 服务端 | 10 年 + 服务器研发 + 两复杂 B 端项目 | **中** | **资深后端**；面试定级看方案与故障深度 |
| 业务域 | 指挥调度 + 金融洞察 | **中** | 适合 **政企数字化、金融科技、B2B 平台**；不适合纯 C 端消费互联网（除非自证高并发） |
| MySQL | 自述熟练 + 十年 | **低–中** | 默认 **业务开发 + 一定建模**；**慢查询治理** 是否到「专项」需面试证实 |
| 前端协作 | Vue/JS 熟悉 | **低** | 全栈协作加分，**勿主投前端** |
| Python | 熟悉 | **低** | 脚本/协作，非主投算法 |
| PostgreSQL | 未述 | **无** | 简历 **不写精通** |
| AI 生产 | 未述 | **无** | **不主投 AI 工程师**；Ten 年 Java + 金融/政企 narrative 可投 **「Java 后端 + 大模型落地」** 仅作副线且 JD 偏工程 |
| 技术影响力 | 未述是否带人/架构 | **低** | **Staff / 平台架构** = stretch，非默认符合 |

### 3.2 较可能具备（与 10 年 + 两项目一致）

- 服务端模块 **长期 Owner** 或核心开发（调度流程、接口层、业务服务）
- Spring 生态、REST/内部 RPC、权限、日志与运维配合
- MySQL 在业务中的建模、事务、常见性能问题处理
- **多系统对接、需求方多、上线与变更** 类「生产责任」经验
- 金融/政企场景对 **稳定、权限、审计** 的常规要求

### 3.3 尚未被材料证明（深挖面）

- 具体 **QPS / 数据量 / 可用性指标**（指挥调度若有实时峰值，是加分项）
- 慢 SQL 体系化治理、PG、缓存/MQ/K8s 深度
- 带人、架构委员会、跨部门技术决策 **Owner**
- AI/RAG/Agent **生产**

## 四、职级与薪资区间（北京，10 年）

> 粗估，非承诺；面试与当前公司背景浮动大。

| 叙事 | 匹配度 | 月薪参考（税前） |
|------|--------|------------------|

**建议对外职级**：简历与 Boss 直聘主投 **「资深 Java 后端 / 高级 Java 后端（10 年）」**；若面试强可谈到 **专家/架构（应用向）**。

## 五、岗位匹配矩阵（v2）

### 5.1 主投 P0

| 岗位关键词 | 匹配理由 |
|------------|----------|
| **资深 Java 后端 / 高级 Java 后端（5–10 年+）** | 10 年 + 双复杂 B 端项目 |
| **Java 服务器开发 / 服务端研发** | 与现头衔一致 |
| **Java 后端 + 金融 / 保险 / 金融科技** | 阳光金融客户洞察直接相关 |
| **Java 后端 + 政企 / 调度 / 应急 / 物联网平台** | 指挥调度系统直接相关 |
| **Java 后端 + 企业数字化 / B 端平台** | 两项目均属此类 |

**投递策略**：

- 主头衔：**资深 Java 后端工程师**（或 **服务器研发工程师** 副标题）
- 项目放前：**指挥调度**（复杂度/可靠）+ **客户洞察**（金融/数据）
- **不写**：PG 专家、AI 工程师、架构师（除非 JD stretch 且你能讲清方案）

### 5.2 主投 P1

| 岗位关键词 | 说明 |
|------------|------|
| Java + **MySQL** / 数据库（**应用侧**优化） | 十年 MySQL 可谈；避开纯 DBA |
| **技术负责人 / Team Lead**（3–8 人，偏业务后端） | **仅当你有带人经历** |
| 全栈偏后端（Java + Vue） | Vue 为加分 |

### 5.3 副投（甄别 JD）

| 岗位 | 条件 |
|------|------|
| **应用架构师** | JD 偏 **系统设计 + Java 栈**；你能讲两项目架构演进 |
| Java + **PostgreSQL** | JD 无「5 年 DBA」硬杠 |
| Java + **大模型 / RAG**（工程落地） | 标题可为副投；**无 Demo 时回复率可能低** |
| **数据中台 / 客户数据平台**（后端） | 洞察系统相关；非算法岗 |

### 5.4 慎投 / 暂不主投

| 岗位 | 原因 |
|------|------|
| NLP/CV **算法** | 履历不匹配 |
| **Prompt / 纯 AI 应用**（无工程要求） | 十年 Java 叙事浪费 |
| **PostgreSQL DBA** 驻场 / 7×24 | 无 PG 生产 + 与自主性冲突 |
| **Staff / 平台专家**（硬 P7+） | 缺跨组织影响证据 |
| 纯 **C 端高并发**（秒杀/feed） | 需单独准备案例，两项目默认不证明 |
| 外包 **人力驻场** | 与约束冲突 |

### 5.5 雇主类型（北京）

| 类型 | 匹配度 |
|------|--------|
| **金融科技 / 保险科技 / 银行应用** | **很高**（客户洞察） |
| **政务数字化 / 应急 / 城市运行 / 融合通信** | **很高**（指挥调度） |
| **B2B SaaS / 行业软件** | **高** |
| 互联网 **C 端核心业务** | **中**（需额外案例） |
| 云厂商 **数据库/AI 平台** | **低**（专项未证明） |
| 外包驻场 | **低** |

## 七、简历与面试叙事（v2）

### 7.1 推荐主叙事

> **10 年服务器（Java）研发。主导/核心参与智慧融合指挥调度系统（多系统融合、高可靠 B 端）与阳光金融客户洞察系统（金融域客户数据与业务服务）。精通 Java，熟练 MySQL，具备 Vue/Python 协作能力。**

### 7.2 两项目建议突出角度（按真实经历取舍）

| 项目 | 简历可写（需属实） | 面试准备 |
|------|-------------------|----------|
| 智慧融合指挥调度系统 | 融合对接、调度流程、实时/准实时、权限审计、上线保障 | 1 个 **可靠性/集成** 难点 + 结果 |
| 阳光金融客户洞察系统 | 客户标签/洞察接口、数据一致性、金融合规边界 | 1 个 **数据/SQL/业务规则** 难点 + 结果 |

### 7.3 弱化项（仍无证据则不写）

- PostgreSQL 专家、AI 工程师、DBA
- 空洞的「精通高并发」— 改为你有的 **调度峰值 / 批处理规模 / 表量级**

### 7.4 面试定级关键（决定能否拿到 45k+）

1. 两项目各 **1 个** 你负责边界最深的技术点  
2. **1 次** 生产问题或性能问题：现象 → 定位 → 改动 → 结果  
3. MySQL：能否讲到 **索引/慢查询/事务** 中的至少一项 **真实案例**  
4. 10 年为何换工作、期望 **资深 vs 架构** 与薪资 band 一致

## 八、综合结论（v2）

| 问题 | 答案 |
|------|------|
| **现在是什么水平？** | **资深 Java 后端 / 服务器研发（10 年）**；政企调度 + 金融洞察 **双域 B 端**；PG/AI 生产未证明 |
| **最适合找什么岗？** | **资深/高级 Java 后端**；**金融/保险/金融科技**；**政企数字化/调度/应急**；**B2B 行业平台** |
| **可以 stretch 什么？** | 应用架构师、Tech Lead（小团队）、Java + 应用侧数据库优化 |
| **不宜主投什么？** | 算法、DBA 驻场、纯 Prompt、Staff/云 PG/AI 平台专家 |
| **10 年是否 under-sell 投「高级」？** | **是**；主投应抬到 **资深**，高级仅作保底 |
| **自主性能否满足？** | **能**；选 **产品型金融科技、行业 SaaS、政企产品公司（非驻场）** 的后端 Owner/核心岗 |
| **评估可靠度** | **中**；年限与项目域已提升置信度；技术深度仍靠面试与你补充附录 |
| **面试校正** | 见 **[005-interview-assessment.md](./005-interview-assessment.md)**：实际为 **高级+~资深-（行业后端）**，宜收窄至调度/视讯/政企+金融标签 |
