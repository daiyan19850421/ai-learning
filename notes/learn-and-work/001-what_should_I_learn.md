# 约束

- 目前能力：内部后台（愿意做更多尝试）；精通 Java；熟悉 Python、JS、Vue（可以触更多语言）。
- 时间：平均每天 4 小时以上，共 30 天
- 学习一个当前比较紧缺的岗位的技能
- 不是很多人都愿意学的，但是学完很好找工作的
- 这种岗位的公司文化相对比较开放、加班少的
- 自主性：希望工作内容有一定自主决策空间，而非纯执行
- 办公地点：北京

## 推荐方向：PostgreSQL 深度工程（性能 + 可靠性）

### 为什么符合「紧缺且多数人不愿学」

- 国内大量 Java 后台能写 CRUD、能接 MyBatis，但**不会**读 `EXPLAIN (ANALYZE, BUFFERS)`、不会治理慢查询、不会设计 HA（Patroni / 流复制）、不会写故障 runbook。
- 市场缺口不在「会不会 SELECT」，而在「生产上谁对延迟、连接池、Vacuum、备份恢复负责」——很多人把这类工作视为「DBA 的事」或「太枯燥」，主动深挖的少。
- PostgreSQL 在国内增速快（互联网、金融科技、政务数字化、云 RDS），但专门人才池小于 MySQL，**竞争者相对少**。

### 为什么符合「文化开放、加班少、自主性」

这类能力的价值体现在**判断与方案**，而不是纯执行：

- 自主性高的信号：慢查询根因分析、索引与迁移方案、连接池与事务边界、监控指标设计、自动化减少 toil。
- 自主性低的信号（需避开）：只备份巡检、7×24 工单响应、驻场、大促值守且无工程化改进空间。

雇主类型上，**产品型 SaaS、出海团队、云厂商数据库平台/管控线、金融科技基础设施小团队** 更常出现「后端 + 数据库治理」合一角色，文化相对开放；传统金融驻场 DBA、外包交付岗自主性低且加班模式差。

### 为什么适合你的履历与 30 天窗口

- 继续用 **「Java 后端工程师」** 作为主头衔求职，PG 作为**可验证专项**；不必硬刚「5 年 PostgreSQL DBA」标签。
- 30 天可交付、且面试可追问验证的产出：
  1. 慢查询治理笔记（含真实 `EXPLAIN` 与前后对比）
  2. Java（Spring Boot）+ PG 压测对比仓库（索引前后、连接池参数）
  3. 故障 / 演练 runbook（连接池打满、长事务、复制延迟等）
  4. 5 道口述题（如何判断加什么索引、Seq Scan 何时合理等）

### 目标岗位（北京求职关键词）

主投（入口最宽）：

- `Java 后端` + `PostgreSQL` / `慢查询` / `性能优化`
- `高级后端工程师` + `数据库`

副投：

- `数据库开发工程师` + `PostgreSQL`
- `数据库平台` / `管控平台` + `PostgreSQL`（云厂商，门槛更高）

慎投 / 需甄别 JD：

- 纯 `PostgreSQL DBA` 且强调 5 年+、7×24、驻场

远程 / 外企（6–12 个月后作增量，英语 B2 更有利）：

- Database Reliability Engineer (DBRE)
- Senior Backend（JD 明确要求 PG 治理）

## 不推荐作为主方向的原因（简述）

| 方向 | 原因 |
|------|------|
| 纯云原生 / K8s SRE | 学习者多，30 天难以与「会部署 + 会写 YAML」的候选人拉开差距 |
| 换栈到 Go 基础设施 | 丢弃 Java 年限叙事，30 天不够建立生产可信度 |
| 纯 DBA 驻场 / 外包 | 与「自主性、加班少」约束冲突概率高 |
| 大模型应用开发 | 拥挤、迭代快，与「多数人不愿学」约束不符 |

## 30 天学习路径（概要）

每天 4h+，按周推进；第 3 周起同步投递「Java 后端 + PG」岗。

| 周 | 主题 | 产出 |
|----|------|------|
| 1 | 执行计划与索引：EXPLAIN、pg_stat_statements、索引类型与失效场景 | 2 个慢查询优化案例笔记 |
| 2 | 连接池、事务、锁：HikariCP、长事务、死锁与 `pg_locks` | 压测仓库 v1 |
| 3 | 可靠性与可观测：复制、备份 PITR 概念、Prometheus 指标、runbook | runbook 初稿 + 压测 v2 |
| 4 | 面试叙事与投递：作品集整理、目标 JD 列表、模拟追问 | GitHub 仓库 README + 简历专项一节 |
