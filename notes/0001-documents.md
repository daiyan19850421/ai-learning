# Documents
在项目的开发过程中，发现向 AI 提问时，它可以结合项目现有的信息总结出最贴合项目的答案。因此，基于这些经验，决定先从这些内容开始着手学习。这样可以快速帮助提高当下的开发效率。

---

## 如何维护文档
将项目所有有关的信息全部放到项目的 docs 目录下，按优先级做到：
- 准确：准确是第一原则。如果文档内容没有写对或者过时了，会导致 AI 根据错误的文档进行分析并输出结果。因此，如果不确定的可以先不落到文档，落到文档的务必准确，并要做到根据实际发生的变化及时修改文档。可以理解为，AI 时代最关键的开发步骤就是先维护好文档。
- 全面：项目相关的内容都要落到项目的代码库中，这样 AI 会帮助开发人员考虑到所有的情况，给出最准确的答案或代码。比如，给出了服务器的防火墙配置，AI 就知道服务级别的安全配置如何做了。可以考虑在研发的过程中所有做的相关工作通过文档记录下来。
- 路径清晰：主要是为了开发人员维护文档更方便，避免找不到文档，或者盲目增加重复的文档变得难以维护。

---

## 如何引导 AI 读文档

- 推荐结构

```text
project/
├── AGENTS.md                 # AI 入口：项目一句话、约束、常用命令、docs 索引
├── README.md                 # 给人看的简介与上手说明，可以告诉 AI 应该读 AGENTS.md
├── docs/
│   ├── README.md             # 文档总目录：列出所有文档及适用场景
│   ├── architecture/         # 架构与边界
│   │   ├── overview.md       # 系统全貌、模块职责
│   │   └── decisions.md      # 重要技术决策（为何这样选）
│   ├── product/              # 业务与需求
│   │   ├── glossary.md       # 术语表（统一 AI 与人的用词）
│   │   └── flows.md          # 核心业务流程
│   ├── engineering/          # 研发约定
│   │   ├── coding-style.md   # 代码规范、目录约定
│   │   ├── testing.md        # 测试策略与如何跑测
│   │   └── git-workflow.md   # 分支、提交、评审约定
│   ├── ops/                  # 运维与环境（按需）
│   │   ├── environments.md   # 环境差异、配置项含义
│   │   ├── deploy.md         # 部署与回滚
│   │   └── security.md       # 防火墙、权限、密钥管理原则（勿写真实密钥）
│   └── runbooks/             # 排障与操作手册（按需）
│       └── common-issues.md
├── .cursor/rules/            # 仅放「按路径生效」的细规则（可选）
│   └── *.mdc
└── src/ ...
```

- 文档的维护要点
  - 入口短：入口就是 [AGENTS.md](../AGENTS.md)，要把它维护成一个尽量精炼的文本而不是大段大段的陈述性的文档
  - 细节分册：详细内容全部放进 `docs/`，按主题拆分，避免重复和过时。

- AGENTS.md
  - 在 Cursor 里，根目录的 [AGENTS.md](../AGENTS.md) 就是给 Agent 提供的默认入口，系统会把它当作项目级说明自动载入。
  - 官方把它和 .cursor/rules 并列。
  - 专供 AI 阅读，可以一开始就声明并引导人去读 [README.md](../README.md)
  - 给 AI 提供一系列约束、规则、指引，按照定义好的方式去回答问题、维护项目

- .cursor/rules/
  - Cursor 的项目级规则，在与 Agent 对话时按条件注入上下文
  - 可以再分子目录
  - 必须是 `.mdc` 文件， 其它格式不会被识别
  - 文件格式：
  ```text
  ---
  description: React 组件约定
  globs: src/components/**/*.tsx
  alwaysApply: false
  ---

  - 使用 named export，不用 default export
  - 样式用 Tailwind，不写内联 style
  - 组件超过 200 行就拆分子组件
  ```
  - alwaysApply：true 代表每次对话都加载
